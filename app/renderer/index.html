「均速外推」照最近几天的整体节奏（空闲时间摊薄在内）；「每天 N 小时」按近 3 天每活跃小时的实测点数消耗推演（账本里有支出的分钟才算活跃）。到重置时间还没打满就显示「到期耗不尽」——窗口一重置额度即回满。
界面上的数字分两类，标记区分：
精确（无标记）——① 点数/百分比：来自 Mirasim /v1/limits，账号级权威；② 美元主行：本机账本 token × 官方 API 价直接求和，可与 Mirasim「设置 → 流量监控 → 估算成本」列逐笔核对（同一份账本、同一张价目表）。
推算（带 ≈）——满额$ / 余$ / 账号级已用$。额度上限以「点」计价，云端不提供点→美元的官方汇率（/v1/limits 是唯一接口，无成本端点），只能反推。满额给出两个口径对照：
　·「标定」逐对「Δ本机账本$ ÷ Δ已用点数」取按点数加权的中位数，抗单点失真与他机污染；
　·「点数反推」直接用账号级已用点数反推：本机账本$ ÷ 已用点数 × 预算点，使用官方点数但不是云端美元账单。
　两者接近＝账本与点数自洽，可放心用；分歧大＝至少一侧失真（多机同时用、或账本尚未回填）。带 ⁻ 号表示该窗口是模型档位窗，分桶自档位声明起才累积，此口径系统性偏低。
美元性质：按官方 API 价折算的等价估值，不是订阅账单——订阅按窗口额度计费，不按 token 扣款。
分家族：窗口卡末行按模型家族（Claude / GPT …）拆分。美元＝该家族账本实测；点数＝官方点数增量按同期各家族账本美元占比归因（增量静置 5 分钟等 relay 回填 token 再分摊）。同期无任何账本支出的增量记「未归因」（他机用量）。点数归因自本版部署起累积，更早的用量拆不出家族。
今天：自然日 0 点起。点数＝官方点数增量逐段累加（账号级，含其他设备；本机停机时段按前后差值补账，重置瞬间跨越的一小段宁漏勿错）；美元＝本机账本。两者口径不同，不能互相换算核对。
多机：本机并发多会话已全量计入账本；其他设备的用量只体现在点数、不入本机账本。标定对此有两道防线——检测到他机活跃段整段剔除，聚合取中位数。
