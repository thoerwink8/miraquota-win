fable 点数计量倍率
这里填的是每美元口径的倍率——填 2（官方：同样一份支出，fable 扣 2 倍点）。 换成每 token口径是 4 倍：fable 标价 $10/$50 本身就是 opus $5/$25 的两倍，之上再罚两倍。 别把 4 填进来，所有美元数会一起翻倍。改完立即生效，存在 ~/.miraquota/settings.json。

精确（无标记）——点数与百分比来自 /v1/limits，账号级权威；美元主行是本机账本 token × 官方 API 价，可与 Mirasim「流量监控 → 估算成本」逐笔核对。
满额 / 余 / 账号级已用——官方口径：额度点 ÷ 100 = 美元（官方已确认）。档位卡再除以倍率， 给的是「拿这个档位真能花掉多少」——fable 子上限 296,800 点只兑得出 $1,484。
折算（仅总窗）——fable 每美元扣 2 倍点，主行的账本原值放大后才与满额同尺。
账本对表——本机账本反推的单价与官方 0.01 的偏离，就是账本漏计的幅度，在上面「单价」里。
美元性质——按官方 API 价折算的等价估值，不是订阅账单。
分家族——美元是账本实测；点数按同期各家族账本占比归因，同期无本机支出的记「未归因」（他机用量）。归因自本版部署起累积。
今天——自然日 0 点起。点数含其他设备，美元只算本机，两者不能互相换算。
多机——他机用量只进点数、不进本机账本；标定会整段剔除他机活跃期。
推算——本机 Mirasim 没在跑时：另一台还连着的机器会把它读到的账号额度随分片送来， 满额与他人占用都用那份（额度点是账号级的，谁读到都一样），顶栏写明是哪台、多久前读的； 一台都没有时才退回本机窗口锚点滚动推算，那时他人占用确实看不见。
连自建服务器
推荐这条：账本与账号额度都汇总在自己的服务器上，各机秒级同步， 口径只算一遍。地址已预填，只要粘一个 token（在服务器的 /var/lib/miraquota-hub/config.json 里）。

为什么要合并：点数是账号级的，账本是本机级的。多机共用一份额度时 「本机账本$ ÷ 账号已用点」系统性偏低，合并后单价、归因、活跃强度才与官方同口径。
失败会怎样：只是样本变少，美元退回本机口径，不会算错——点数与百分比始终直连云端。 黄色不用管，红色才看网络与凭据。
每台机器的 7 天用量：各机自己的账本（fable 按倍率折算）÷ 100，与官方点数同尺。 「未同步账本的机器」是残差——账号已用点减掉各机之和：没跑 MiraQuota 的人、关了同步或分片过期的机器， 以及各机账本自己的时差漏记（relay 每 3 分钟回填 token，分片最多落后一轮）。独用时残差约 3%， 明显超出才说明有人在共用。官方接口只给账号级总数，这是能做到的最细粒度。
「未定价」——经 relay 扣了点、但价目表没有的模型，只能记 token；口径页会提前点名已启用却无价的模型。
怎么同步的：每台机器只写自己的 machine/<机器名> 分支，单提交覆盖不留历史； 读他机只取远程分支内容，不动本机工作区。
