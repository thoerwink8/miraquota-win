# 多机账本合并：原理与部署

## 原理

Mirasim 的额度点是**账号级**（所有机器共用一个池），而本项目的成本账本是**本机级**
（只看得到本机的 transcript 与网关账本）。一个账号在多台机器上同时使用时，所有
「本机账本$ ÷ 账号级点数」口径都会系统性偏低：标定单价被拉低、点数归因错归无主、
强度（点/活跃小时）虚高。

解法：每台机器把本机账本的**聚合态**（分钟桶 buckets/scoped/family + 覆盖区间）序列化
为一个 JSON 分片，经一个**私有 Git 仓**自动互读。合并后：

- `spent / activeMinutes / familySpent` 默认返回本机 + 全部外机分钟桶之和
  （`{ localOnly: true }` 仍可查纯本机口径）；
- 标定观测的分子已含他机支出，只有「在场每台外机分片的 coverage 都盖住该观测」的时段
  才豁免他机剔除（覆盖门）；不全覆盖的时段沿用原有 CARRY_TIMEOUT 剔除兜底；
- 点数归因的静置放宽为 max(300, 2×intervalSec)——外机支出要等它下一轮发布分片才可见。

通道设计：每台机器只写自己的分支 `machine/<machineId>`（hostname 清洗的短名），
**单提交覆盖不留历史**（首次 commit，之后 `commit --amend` + `push --force`），仓库体积
恒定，无清理任务；读他机只 fetch `machine/*` 并 `git show` 文件内容。互不写对方分支，
永无冲突。

## 部署步骤

1. 建一个**私有**空仓（GitHub/Gitea/自建裸仓均可，账本金额属敏感信息，务必私有），
   确保每台机器的 git 凭据能读写它。
2. 每台机器写 `~/.miraquota/sync.json`：

   ```json
   { "remote": "git@github.com:you/miraquota-sync.git", "intervalSec": 600 }
   ```

   `intervalSec` 可省略（默认 600 秒）。**文件不存在或无 remote 时功能完全关闭，
   行为与从前完全一致。**
3. 重启 MiraQuota（桌面版或 provider）。首轮 poll 即同步一次，之后按 intervalSec 节流。

### 新机器免手写：自动接入（v0.6 起）

没有 `sync.json` 的机器，每小时会静默探一次内置的默认仓
（`DEFAULT_REMOTE`，见 `provider/lib/ledger-sync.mjs`）能不能读：

- **能读**（这台机器本来就有本人的 GitHub 凭据）⇒ 自动写好 `sync.json` 并开始同步，
  多机页会注明「探到默认仓可读后自动接入」；
- **读不动**（陌生人装了公开版、没凭据、没网）⇒ 什么都不发生，不记错误也不进界面，
  与「没配置就整个功能关闭」逐字一致。

探测只跑 `git ls-remote`（只读、不建仓、不留痕），且所有后台 git 都禁用交互
（`GIT_TERMINAL_PROMPT=0` / `GCM_INTERACTIVE=never`），不会弹出登录窗口。

**关掉自动接入**：把 `~/.miraquota/sync.json` 的内容改成 `{"autoJoin": false}`——
文件存在就一律不再探测，而无 remote 又意味着同步关闭。直接删文件不行，一小时内会被接回。
4. 验证：面板页签末尾出现「多机」页（未配置时这一页与页签都不存在），状态绿标「GitHub 已接入」，每台机器一行
   「<id> · N 分钟前推送」（本机有标注）；远端仓出现 `machine/<各机器名>`
   分支且各只有 1 个提交；`~/.miraquota/sync-repo` 里只有本机的 `shard.json`。

## 故障表现

红色只留给真要用户处置的持续故障——抖动有三道闸依次拦：单轮内退避重试一次、
发布成功而只读取失败算中间态、仍失败要连续 2 轮（或上次成功已过期）才报红。
四态（payload `sync.state`）：

| state | 颜色 | 含义 |
|---|---|---|
| `ok` | 绿 | 最近一轮发布＋读取都成，且不超过 2×intervalSec |
| `warn` | 黄 | 有失败但没到报红：`pushOk` 为真＝本机已上传、只是读不到他机；否则＝抖动重试中 |
| `error` | 红 | 连续 2 轮失败，或曾成功过但成功记录已过期还在失败 |
| `connecting` | 灰 | 已启用但尚无新鲜的成功记录，且当轮没有失败原因 |

失败原因给两份：`sync.errorHint` 是人话归纳（网络连不上 GitHub / 凭据无效或无权限 /
仓库地址不对，归纳不出就没有这个字段），`sync.error` 是 git 原始报错首行，UI 两个都显示；
`sync.failStreak` 是连续失败轮数。

| 现象 | 含义 | 处置 |
|---|---|---|
| 红标「同步失败：…」 | git push/fetch 连续报错（凭据、网络、远端没建） | 按所附原因修；修好后下一轮自动恢复 |
| 黄标「本机已上传，读取他机失败」 | push 成功、fetch 失败（多为网络抖动） | 不用管：本机数据没丢，下一轮自动补读他机 |
| 黄标「同步重试中」 | 首轮失败，还没到连续 2 轮 | 等下一轮；持续失败会转红 |
| 多机页只有本机一行 | 远端只有本机分支 | 确认其他机器也配了 sync.json 并已跑过一轮 |
| 某机器行标「已过期」 | 该机分片超过 2×intervalSec 未更新（离场或它那边同步中断） | 去那台机器看它的同步状态 |
| 某机器分片过期（generatedAt 早于 8 天保留窗） | 该机器离场，不再参与覆盖门 | 不算错——只是全覆盖时段变少、标定样本减少，兜底剔除仍在 |
| 标定样本比启用前少 | 覆盖门只放行全覆盖时段，其余仍走剔除 | 正常；随各机器持续同步，样本会回升 |
| 同步暂时中断 | 上一轮读到的分片仍留在内存参与合并 | 恢复后自动刷新；重启后需等首轮同步才重新合并 |

## 口径提示

启用同步后，窗口卡的「支出」与今天卡的美元都是**全机合计**（「口径说明」页的多机行有注明）；
未启用时依旧是纯本机口径，两种状态下与官方点数的可比性都取当下能拿到的最完整分子。

## 每台机器花了多少（v0.9.20）

多机页每行机器后面跟着它这 7 天的用量，末尾一条「未接入」。

    每台机器 = 它自己分片里的账本（fable 按倍率折算）÷ 100
    未接入   = 官方 7d 已用点 − 各机之和

官方接口只给账号级一个总数（`/v1/limits` 没有按用户/设备的拆分），所以「谁花的」只能
由各机自己的账本回答——这是能做到的最细粒度。实现：`CostLedger.perMachineSpent()`
不走合并索引（合并的意义正是抹掉机器边界），`Engine#machineUsage()` 组装成 `sync.usage`。

**「未接入」是残差，不是纯他人用量。** 它同时装着两样东西：

1. 真的没跑 MiraQuota 的人（账号共享给别人时就是这一项）；
2. 各机账本自己漏记的部分——未归因点数、relay 尚未回填的 token、分片最多落后一轮。

本机实测账本偏低约 3%（见 QUOTA-ESTIMATION 的「账本对表」），所以残差在 3% 上下时
基本是漏记；明显超出这个量级才说明有人在共用额度。面板上那段说明就是这个意思，
删掉它会让人把「我们的账本不准」读成「别人用了这么多」。

### 残差的名字：「未同步账本的机器」（v0.9.21）

用户 2026-09-02 拍板把残差归成一类：**账本没同步上来的机器**——没跑 MiraQuota 的人、
关了同步的机器、分片过期的机器，外加各机账本自己的时差漏记（relay 每 3 分钟回填 token，
分片最多落后一轮）。旧名「未接入」只让人想到第一种。

同版起账本**不再静默丢行**（`isRelayCharged` 是「会扣点」的全集）：

- dispatch（Mirasim 自己发的中继调用）单列家族「调度」，不混进用户选的计费家族；
- 价目表没有的模型记 token（`ledger.unpriced`，随分片同步），多机页给「未定价 · 模型」一行；
- 价目表读 Mirasim 缓存的全部 provider（官方源优先），不再只读 anthropic / ai-router；
- 口径页对表 `~/.mirasim/setting.json` 的 `enabledModels`，已启用却无价的模型提前点名。

本机排查记录：历史 5,348 条 relay 调用没有一条真正无价；`unpricedRecords` 计的几乎全是
回填前 3 分钟的零 token 行。所以这组改动不会缩小本机残差，它防的是将来——新模型、新来源
一出现就有名有姓。

## 收件口通道：没有 GitHub 的人怎么加入（v0.9.22）

用户 2026-09-02 拍板：共享额度的人没有 GitHub，也不想每加一个人就去开令牌。
于是走一个 Cloudflare Worker（`inbox/`）：分片直接存它的 KV，**不写 GitHub 仓、不需要任何
GitHub 令牌**，唯一的秘密是邀请码。客户端零仓库凭据。git 通道的机器读远端分支之余也顺带
读一次收件口（只读、无鉴权），两条通道的人在同一张多机页上。

```
sync.json（收件口模式）
{ "inbox": "https://miraquota-inbox.<子域>.workers.dev", "account": "fxc", "passphrase": "…" }
```

- **身份**：机器靠首次运行生成的随机 `installId`（`~/.miraquota/install.json`，同名主机不撞）；
  人靠自报名字 + 自设口令，Worker 存 PBKDF2 哈希。名字全局唯一，第一次注册要邀请码
  （额度主人定一次、口头告知），之后同名的第二台机器只要口令。
- **两种客户端**：完整应用在多机页登录；不装软件的机器下载 `<地址>/lite.bat` 双击，
  它建一个每 10 分钟的计划任务，只上传**原始行**（时间、模型、token 数），定价在读它的
  那一端做（`CostLedger.#materialize`），它机器上不带价目表。
- **读**：收件口模式从 Worker 一次拿全所有分片，落缓存供冷启动；git 通道机器的分片不在
  KV 里，所以收件口用户看不到额度主人的机器——主人的机器却看得到所有人（它两边都读）。
- **多机页**按人分组：每人一行汇总，下面缩进列机器；git 通道的机器归「额度主人」。
- **网络**：收件口在 `*.workers.dev`，国内实测 DNS 投毒直连不通（连 1.1.1.1 也被劫持），
  经代理可用。用户 2026-09-03 拍板暂不绑自有域名——登录卡与轻客户端都写明「需开代理」。
  要过墙时给 Worker 绑一个托管在 Cloudflare 的域名即可，代码不用改。
- 部署、加人、撤销见 `inbox/README.md`。它保证「只有知道口令的人能用那个名字」，
  保证不了名字是真的——朋友圈里够用，要防人只有 GitHub 登录那条路。

## Linux 服务器接入 + 看别的机器跑多快（v0.9.27）

用户 2026-09-05 的场景：人在 Windows 上看面板，活却跑在 Linux 服务器上（Mirasim 的
relay 在那台机器上扣点）。于是要两件事——那台机器的账本得进来，它的速度也得看得见。

### 一条命令接入

```
node scripts/deploy-linux.mjs --host <ssh 别名>
```

它做四件事，可重复跑（幂等）：探那台机器够不够条件（node 22+、有没有 `~/.mirasim/insights`）、
把 `provider/` 传到 `/opt/miraquota`、配好同步通道、装一个 systemd 服务
`miraquota-sync`（`provider --sync-only`：不起 feed、不注入、不需要 Mirasim 调试端口，
每分钟读一次账本，按 `intervalSec` 发分片）。

**默认走 git 通道**，密钥是在那台机器上现生成的**部署密钥**（deploy key，只对账本仓有效、
不碰它的其他 GitHub 用途），用本机的 `gh` 装到仓上。为什么不默认走收件口：收件口在
`*.workers.dev`，**看面板的那台机器**（国内）直连不通，服务器发得上去、本机读不回来，
等于没接。那台机器连不上 GitHub 时才 `--via-inbox`。

拆掉：`node scripts/deploy-linux.mjs --host <别名> --uninstall`（保留 sync.json）。

### 速度随分片一起过来

分片多带一个可选的 `speed` 块（`{ rows, sampleTotal }`，就是速度卡那份 report 去掉在途
条目）。**schemaVersion 仍是 1**：老版本读到多出来的字段直接忽略，两代客户端混跑没事；
合并口径一个字节都不读它——它不是账本，进不了 `spent`。

面板上：速度卡多一条机器切换胶囊（**只有别的机器也上报了速度时才出现**），多机页每台
这样的机器行尾多一个「速度 →」。切过去看的是**那台机器的分片快照**，所以卡头写明
「N 分钟前的快照」——最多落后一轮，不是实时值。选中的机器只活在这次会话里，不落盘：
重启后停在一张陈旧的他机快照上，比回本机更让人困惑。

**只有这张卡跟着切。** 额度点是账号级的（同一个 `userId` 的所有设备共用一个池），5 小时 /
7 天那三张卡在哪台机器看都是同一个数；机器级的问题只有两个——谁花的（多机页已有）、
跑什么模型多快（这一版补上）。轻客户端与老版本的机器没有 `speed` 块，界面就不给入口。

## 账号额度也随分片走（v0.9.28）

上一节那句「在哪台机器看都是同一个数」反过来就是这一版：**只要有一台机器还连着 Mirasim，
没连上的机器就不该退回自己那份陈旧锚点去猜满额**。用户 2026-09-05 的场景——活跑在 Linux
服务器上，人在 Windows 上看面板，本机 Mirasim 没开，面板顶着「按 27 分钟前的窗口锚点推算；
他人占用不可见」，而服务器那边每分钟都在读到最新的账号额度。

分片再多带一个可选的 `limits` 块（**schemaVersion 仍是 1**，老版本忽略即可）：

```json
{ "limits": { "capturedAt": 1757000000,
              "windows": [{ "label": "7d", "used": 494270, "budget": 613800, "resetAt": … }] } }
```

- `capturedAt` 是**读到那一刻**，不是发分片那一刻。对面据此判龄期、跟自己的锚点比新旧。
- 收下的一方把它当锚点用（`anchorsFrom()`，与本机实测同一个转换），推算路径原样跑。
  **判据只有一条：谁更近。** 本机刚断线时自己的锚点更近，走本机；断久了走他机，
  连满额换了档位都跟着变。两边都超过 30 天就都不采信，退回纯账本口径。
- 文案分开写：他机读到的是**账号级**数字，别人的占用已经计到采集那一刻了，
  所以是「他人占用已计到那一刻」，不是单机锚点那句「他人占用不可见」。
  payload 另给 `reckonFrom { machineId, account, capturedAt, ageSeconds }`。
- **不给 `points` 字段。** 满额、余、账号级已用都是官方除法（精确），但「已用点」若填成
  推算值，就会印在那个写着「原始额度点，来自 /v1/limits，账号级权威口径」的主行上。
  点数口径在本机没实测时照旧退到美元口径显示。

### 额度那几轮走快节奏

账本迟到十分钟无所谓（它是流水，补上就行），账号额度不一样——本机没实测时它是**唯一**的
额度来源，压着十分钟不发，对面主行印的就是十分钟前的数。于是两头各加一条快节奏
（`quotaIntervalSec`，默认 `min(intervalSec, 120)` 秒）：

| 机器状态 | 行为 |
|---|---|
| 连着 Mirasim（手里有额度快照） | 完整同步改按 `quotaIntervalSec` 触发（发布 + 读取） |
| 连不上 Mirasim（本机无实测） | 额外插一条**只读**拉取 `LedgerSync.refreshOnly()`，省掉 push——本机没有 relay 在扣点，账本几乎不动，没什么可发的 |
| 连得上、也不缺额度 | 一次都不额外发生，与从前逐字一致 |

只读那条失败静默：状态色仍由 `run()` 那条主链判，一次额外的读取失败不该让界面变红。
嫌 git 推得勤就在 `sync.json` 写 `quotaIntervalSec`（填成和 `intervalSec` 一样大即关掉快节奏）。

## 自建服务器（hub）：三条通道收成一条（v0.9.30）

用户 2026-09-05：「账单不需要在 GitHub 同步了……只要连接服务器地址，就能随时获取到
最新的额度统计，不管哪一台机子。」于是有了 `server/`（详见 `server/README.md`）。

**hub 之前**每台机器各自把分片推进私有 git 仓 / Worker，再各自拉回来自己合并、自己标定、
自己算口径 —— 口径每台算一遍、实时性卡在 git 节流上、新机器要凭据或邀请码才进得来。
**hub 之后**机器只管推自己那份，服务器算好整份 payload，面板填个地址就看。

```json
{ "hub": "https://<地址>/mq", "token": "<装的时候打印的>", "intervalSec": 600 }
```

配了 `hub` 就走 hub，不再碰 git 仓与收件口 —— 那两条是「没有服务器时的替代品」。
三条通道现在是一张分派表（`#publishTo` / `#fetchAll`），加第四条只改那两处。

### 「不用装东西」到什么程度

用户问过「能不能靠连接时拿 IP 和主机名，就不要上传器了」。分三种机器：

| 机器 | 要装什么 | 服务器怎么认它 |
|---|---|---|
| 开着面板的 | **什么都不用多装**，app 本身就是上传通道 | 分片自报主机名 + `installId` |
| 无界面服务器 | 已有的 `provider --sync-only` 改个地址 | 同上 |
| 完全不装的 | — | 只知道有这台机器连过，**看不到它花了多少** |

第三类是物理下限：服务器读不到别人的硬盘，不装东西就没人读它的账本，用量仍落在
「未同步账本的机器」那条残差里。要真正做到「一台都不用装」，只有让所有机器的 API
流量走同一个 Mirasim relay —— 那样它的网关账本天然含全部调用，代价是 API 通道也成了单点。

**IP 绝不当身份。** 拨号、切网、走代理，IP 天天变，认它会把一台机器认成五台。
身份一律 `installId`（首次运行生成、落盘不变），IP 只作「从哪连的」显示。

### 账号额度在 hub 上怎么走

服务器上没有 Mirasim，读不了 `/v1/limits`。跑着 Mirasim 的机器 `PUT /limits` 送上去，
服务端经 `Engine.ingestLimits()` 收下 —— 与本机 `poll()` 收自己读到的那份是**同一个方法**，
服务端不长第二套口径。只留最新一份，收到的比在架的旧就不收（慢包后到、机器时钟不齐）。

### 面板只画，不再自己算（v0.9.30）

`provider/lib/hub-client.mjs` 走 SSE（`GET /stream`）：服务器有新数据就推，秒级；
断了自己退避重连。**但不是所有字段都听服务器的** —— 取错一边就是把别人的速度当成自己的，
或者把自己的账本当成全账号的：

| 字段 | 从哪来 | 为什么 |
|---|---|---|
| 额度窗口、单价、今天、档位倍率 | **服务器** | 它手里有全部机器的账本，本机算不全 |
| `speed` | 本机 | 这台机器自己的实测速度；服务器只有分片里落后一轮的快照 |
| `roster` | 本机 | 对表**这台机器**的 `~/.mirasim/setting.json` |
| `sync` | 本机 | 这台机器与服务器的连接状态，本来就是本机的事 |
| `buckets` / `pricing` | 本机 | 本机读数，排查用 |

名单就是 `LOCAL_FIELDS`，加字段时照着上面那句判：**服务器上有没有这台机器的这个东西**。
本机没有某个机器级字段时，服务器那份里的同名字段也不顶上（不拿别人的凑数）。

服务器不可用或数据超过 `HUB_STALE_AFTER`（70 秒，服务器 25 秒一次心跳）时，
**原样退回本机自算的那份** —— 降级路径与没配 hub 时逐字一致，不白屏。
用上服务器那份时面板会在顶栏写「服务器汇总 · N 台机器」：本机 Mirasim 没开却显示精确值，
不说明来源会被当成出错了。

### 新机器怎么接（不用 SSH）

多机页第一张卡「连自建服务器」：地址已预填（`DEFAULT_HUB`），只要粘一个 token。
`connectHub()` 先探 `/health` 确认是 MiraQuota 服务器，再用写接口验 token，
**都过了才写配置** —— 写完才发现地址错了，用户看到的是「同步失败」而不是「地址填错了」。

### 单点怎么办

服务器挂了所有人都看不到 —— 这是 hub 换来实时与单一口径的代价。缓解：客户端的
`inbox-shards.json` 缓存与本机降级路径（锚点推算、纯账本口径）全部保留，
上一节那套「他机额度快照当锚点」也还在，所以断开时退回的是从前的行为，不是白屏。
