# 多机账本合并：原理与部署

> **2026-09-24 起这里只管账本、速度与流水，不管账号额度。** 账号额度只认两个来源：本机
> `/v1/limits` 实读，与 fleet-dao 的额度表（面板「账号池」页，见 `provider/lib/fleet-source.mjs`）。
> hub 通道客户端与「额度随分片走」同日下线，原因见文末。

## 原理

Mirasim 的额度点是**账号级**（所有机器共用一个池），而本项目的成本账本是**本机级**
（只看得到本机的 transcript 与网关账本）。一个账号在多台机器上同时使用时，所有
「本机账本$ ÷ 账号级点数」口径都会系统性偏低：标定单价被拉低、点数归因错归无主、
强度（点/活跃小时）虚高。

解法：每台机器把本机账本的**聚合态**（分钟桶 buckets/scoped/family + 覆盖区间）序列化
为一个 JSON 分片，与其它机器互读。合并后：

- `spent / activeMinutes / familySpent` 默认返回本机 + 全部外机分钟桶之和
  （`{ localOnly: true }` 仍可查纯本机口径）；
- 标定观测的分子已含他机支出，只有「在场每台外机分片的 coverage 都盖住该观测」的时段
  才豁免他机剔除（覆盖门）；不全覆盖的时段沿用原有 CARRY_TIMEOUT 剔除兜底；
- 点数归因的静置放宽为 max(300, 2×intervalSec)——外机支出要等它下一轮发布分片才可见。

## 通道：收件口

| 配置文件 | 服务器要什么 |
|---|---|
| `{ "inbox": "https://…workers.dev", "account": "…", "passphrase": "…" }` | 部署 `inbox/` 到 Cloudflare Workers，只认名字+口令+邀请码 |

HTTP：发布 = 一次 PUT（分片），读取 = 一次 GET（全部分片，剔掉自己）。流水明细（`PUT /journal`）
推的机器放上去、读的机器写进自己的库；分片与明细盖住同一分钟时只算一次（按 (机器, 分钟) 逐格让明细优先）。

退役的两条，配着它们的老 `sync.json` 一律当「未配置」处理，启动日志与多机页的登录卡会说清怎么换：

- **git 通道**（把分片提交进一个私有 GitHub 仓）2026-09-23 退役：用户「不要存 Github，占项目大小和
  烧 cpu」——实测每台机器每 10 分钟要提交 333 KB（≈47 MB/天），还要一把用 `gh` 装的部署密钥；
- **hub 通道**（自建服务器）2026-09-24 下线：见文末。

## 部署步骤

1. 部署收件口（`inbox/README.md`）。
2. 每台机器在多机页登录（名字 + 口令，第一次要邀请码），或手写 `~/.miraquota/sync.json`：

   ```json
   { "inbox": "https://…workers.dev", "account": "<名字>", "passphrase": "<口令>", "intervalSec": 600 }
   ```

   `intervalSec` 可省略（默认 600 秒）。**文件不存在、或没有可用的收件口配置时功能完全关闭，
   行为与从前完全一致。**

   Linux 机器不用手写：`node scripts/deploy-linux.mjs --host <ssh 别名> --via-inbox`
   会送代码、注册、写配置、装 systemd 服务（已有 `sync.json` 一律不动，要换通道加 `--reset-sync`）。
3. 重启 MiraQuota（桌面版或 provider）。首轮 poll 即同步一次，之后按 intervalSec 节流。
4. 验证：面板页签末尾出现「多机」页（未配置时这一页与页签都不存在），状态绿标「已接入」，
   每台机器一行「<id> · N 分钟前推送」（本机有标注）。

## 故障表现

红色只留给真要用户处置的持续故障——抖动有三道闸依次拦：单轮内退避重试一次、
发布成功而只读取失败算中间态、仍失败要连续 2 轮（或上次成功已过期）才报红。
四态（payload `sync.state`）：

| state | 颜色 | 含义 |
|---|---|---|
| `ok` | 绿 | 最近一轮发布＋读取都成，且不超过 2×intervalSec |
| `warn` | 黄 | 有失败但没到报红：`pushOk` 为真＝本机已上传、只是读不到他机；否则＝抖动重试中 |
| `error` | 红 | 连续 2 轮失败，或曾成功过但成功记录已过期还在失败 |
| `connecting` | 灰 | 已启用但尚无新鲜的成功记录，且当轮没有失败原因 |

失败原因给两份：`sync.errorHint` 是人话归纳（网络连不上 / 名字或口令不对 /
收件口地址不对，归纳不出就没有这个字段），`sync.error` 是原始报错首行，UI 两个都显示；
`sync.failStreak` 是连续失败轮数。

| 现象 | 含义 | 处置 |
|---|---|---|
| 红标「同步失败：…」 | 推送/读取连续报错（口令、网络、收件口地址） | 按所附原因修；修好后下一轮自动恢复 |
| 黄标「本机已上传，读取他机失败」 | 推送成功、读取失败（多为网络抖动） | 不用管：本机数据没丢，下一轮自动补读他机 |
| 黄标「同步重试中」 | 首轮失败，还没到连续 2 轮 | 等下一轮；持续失败会转红 |
| 多机页只有本机一行 | 收件口上只有本机那份 | 确认其他机器也登录了并已跑过一轮 |
| 某机器行标「已过期」 | 该机分片超过 2×intervalSec 未更新（离场或它那边同步中断） | 去那台机器看它的同步状态 |
| 某机器分片过期（generatedAt 早于 8 天保留窗） | 该机器离场，不再参与覆盖门 | 不算错——只是全覆盖时段变少、标定样本减少，兜底剔除仍在 |
| 标定样本比启用前少 | 覆盖门只放行全覆盖时段，其余仍走剔除 | 正常；随各机器持续同步，样本会回升 |
| 同步暂时中断 | 上一轮读到的分片仍留在内存参与合并 | 恢复后自动刷新；重启后需等首轮同步才重新合并 |

## 口径提示

启用同步后，窗口卡的「支出」与今天卡的美元都是**全机合计**（「口径说明」页的多机行有注明）；
未启用时依旧是纯本机口径，两种状态下与官方点数的可比性都取当下能拿到的最完整分子。

## 每台机器花了多少（v0.9.20）

多机页每行机器后面跟着它这 7 天的用量，末尾一条「未接入」。

    每台机器 = 它自己分片里的账本（fable 按倍率折算）÷ 100
    未接入   = 官方 7d 已用点 − 各机之和

官方接口只给账号级一个总数（`/v1/limits` 没有按用户/设备的拆分），所以「谁花的」只能
由各机自己的账本回答——这是能做到的最细粒度。实现：`CostLedger.perMachineSpent()`
不走合并索引（合并的意义正是抹掉机器边界），`Engine#machineUsage()` 组装成 `sync.usage`。

**「未接入」是残差，不是纯他人用量。** 它同时装着两样东西：

1. 真的没跑 MiraQuota 的人（账号共享给别人时就是这一项）；
2. 各机账本自己漏记的部分——未归因点数、relay 尚未回填的 token、分片最多落后一轮。

本机实测账本偏低约 3%（见 QUOTA-ESTIMATION 的「账本对表」），所以残差在 3% 上下时
基本是漏记；明显超出这个量级才说明有人在共用额度。面板上那段说明就是这个意思，
删掉它会让人把「我们的账本不准」读成「别人用了这么多」。

### 残差的名字：「未同步账本的机器」（v0.9.21）

用户 2026-09-02 拍板把残差归成一类：**账本没同步上来的机器**——没跑 MiraQuota 的人、
关了同步的机器、分片过期的机器，外加各机账本自己的时差漏记（relay 每 3 分钟回填 token，
分片最多落后一轮）。旧名「未接入」只让人想到第一种。

同版起账本**不再静默丢行**（`isRelayCharged` 是「会扣点」的全集）：

- dispatch（Mirasim 自己发的中继调用）单列家族「调度」，不混进用户选的计费家族；
- 价目表没有的模型记 token（`ledger.unpriced`，随分片同步），多机页给「未定价 · 模型」一行；
- 价目表读 Mirasim 缓存的全部 provider（官方源优先），不再只读 anthropic / ai-router；
- 口径页对表 `~/.mirasim/setting.json` 的 `enabledModels`，已启用却无价的模型提前点名。

本机排查记录：历史 5,348 条 relay 调用没有一条真正无价；`unpricedRecords` 计的几乎全是
回填前 3 分钟的零 token 行。所以这组改动不会缩小本机残差，它防的是将来——新模型、新来源
一出现就有名有姓。

## 收件口通道：没有 GitHub 的人怎么加入（v0.9.22）

用户 2026-09-02 拍板：共享额度的人没有 GitHub，也不想每加一个人就去开令牌。
于是走一个 Cloudflare Worker（`inbox/`）：分片直接存它的 KV，**不写任何仓、不需要任何
GitHub 令牌**，唯一的秘密是邀请码。客户端零仓库凭据。

```
sync.json（收件口模式）
{ "inbox": "https://miraquota-inbox.<子域>.workers.dev", "account": "fxc", "passphrase": "…" }
```

- **身份**：机器靠首次运行生成的随机 `installId`（`~/.miraquota/install.json`，同名主机不撞）；
  人靠自报名字 + 自设口令，Worker 存 PBKDF2 哈希。名字全局唯一，第一次注册要邀请码
  （额度主人定一次、口头告知），之后同名的第二台机器只要口令。
- **两种客户端**：完整应用在多机页登录；不装软件的机器下载 `<地址>/lite.bat` 双击，
  它建一个每 10 分钟的计划任务，只上传**原始行**（时间、模型、token 数），定价在读它的
  那一端做（`CostLedger.#materialize`），它机器上不带价目表。
- **读**：从 Worker 一次拿全分片（KV 按 shard:<名字>--<installId12> 分键），落缓存供冷启动；
  流水明细只回同一个账号的（明细里有会话 id 与工作区路径）。
- **多机页**按人分组：每人一行汇总，下面缩进列机器。
- **网络**：收件口在 `*.workers.dev`，国内实测 DNS 投毒直连不通（连 1.1.1.1 也被劫持），
  经代理可用。用户 2026-09-03 拍板暂不绑自有域名——登录卡与轻客户端都写明「需开代理」。
  要过墙时给 Worker 绑一个托管在 Cloudflare 的域名即可，代码不用改。
- 部署、加人、撤销见 `inbox/README.md`。它保证「只有知道口令的人能用那个名字」，
  保证不了名字是真的——朋友圈里够用，要防人只有 GitHub 登录那条路。

## Linux 服务器接入 + 看别的机器跑多快（v0.9.27）

用户 2026-09-05 的场景：人在 Windows 上看面板，活却跑在 Linux 服务器上（Mirasim 的
relay 在那台机器上扣点）。于是要两件事——那台机器的账本得进来，它的速度也得看得见。

### 一条命令接入

```
node scripts/deploy-linux.mjs --host <ssh 别名>
```

它做四件事，可重复跑（幂等）：探那台机器够不够条件（node 22+、有没有 `~/.mirasim/insights`）、
把 `provider/` 传到 `/opt/miraquota`、配好同步通道、装一个 systemd 服务
`miraquota-sync`（`provider --sync-only`：不起 feed、不注入、不需要 Mirasim 调试端口，
每分钟读一次账本，按 `intervalSec` 发分片）。

**通道靠参数显式给**：`--via-inbox`。不给时只装服务并提示——不猜、也不去任何地方装密钥。
为什么不默认收件口：收件口在 `*.workers.dev`，**看面板的那台机器**（国内）直连不通，
服务器发得上去、本机读不回来，等于没接。还配着 hub 的机器用 `--reset-sync --via-inbox` 换过来。

拆掉：`node scripts/deploy-linux.mjs --host <别名> --uninstall`（保留 sync.json）。

### 速度随分片一起过来

分片多带一个可选的 `speed` 块（`{ rows, sampleTotal }`，就是速度卡那份 report 去掉在途
条目）。**schemaVersion 仍是 1**：老版本读到多出来的字段直接忽略，两代客户端混跑没事；
合并口径一个字节都不读它——它不是账本，进不了 `spent`。

面板上：速度卡多一条机器切换胶囊（**只有别的机器也上报了速度时才出现**），多机页每台
这样的机器行尾多一个「速度 →」。切过去看的是**那台机器的分片快照**，所以卡头写明
「N 分钟前的快照」——最多落后一轮，不是实时值。选中的机器只活在这次会话里，不落盘：
重启后停在一张陈旧的他机快照上，比回本机更让人困惑。

**只有这张卡跟着切。** 额度点是账号级的（同一个 `userId` 的所有设备共用一个池），5 小时 /
7 天那三张卡在哪台机器看都是同一个数；机器级的问题只有两个——谁花的（多机页已有）、
跑什么模型多快（这一版补上）。轻客户端与老版本的机器没有 `speed` 块，界面就不给入口。

## 下线的两条额度路：分片捎额度（v0.9.28）与 hub 通道（v0.9.30）——2026-09-24

这两条都是为了回答同一个问题：**本机 Mirasim 没开时，账号额度从哪来**。v0.9.28 让连着
Mirasim 的机器把读到的额度随分片捎过来；v0.9.30 的自建服务器（`server/`）再收一份、算好整份
payload 经 SSE 推给面板。2026-09-24 起这个问题由 fleet-dao 回答——它在服务器上统一读所有账号池
（Claude 两个组织、Mirasim、Cursor、Grok、Jev…），MiraQuota 只做它的桌面窗口（「账号池」页）。
同一个账号的额度留两个远端来源，只会多出「该信谁」这个本来不存在的问题，所以两条一起下线：

- 客户端删掉：`hub-client.mjs`（SSE 与逐字段合并）、`LedgerSync` 的 hub 模式（`connectHub` /
  `pushLimits` / 分派表）、`DEFAULT_HUB`、hub 通道的快节奏与「有新动静就早发」、分片里的 `limits`
  块与 `quotaIntervalSec` / `refreshOnly()` 那套只读拉取、多机页「连自建服务器」那张卡、
  `deploy-linux --hub`。老版本推来的、还带 `limits` 的分片照常合并账本，额度一个字不采信。
- **服务端先不动**：`server/` 与 `scripts/deploy-hub.mjs` 留着，接住停服前还没升级的老客户端；
  切换完成、停服那一步再把它们连同 `test/hub.test.mjs` 与 `Engine` 的 `noLocal` 分支一起删。
- 下线后少了的东西（如实写）：配 hub 的机器看不到别的机器的速度与账本合并了——要继续，就在多机页
  用收件口登录（Linux 服务器 `deploy-linux --reset-sync --via-inbox`）。流水明细也随之只走收件口。
